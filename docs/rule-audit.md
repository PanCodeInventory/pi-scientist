# Scientist 规则归类与改革边界

恢复点：`e39df4b`，已推送到 `origin/main`。本清单依据旧版实际代码/提示/Skills 归类，不把“复杂”“MUST”或“固定格式”当作删除理由。

## 判定方法

1. 假设模型完全可靠，用户是否仍希望遵守？是：工作规范或正确性要求。
2. 换一种工作路径是否仍可满足同一需求？是：路径通常是可替换机制。
3. 违反后损失的是交付兼容/用户偏好、科学有效性，还是仅仅少走一步？
4. 混合规则先拆出目标与手段；无法判断归属的要求保守保留。

## A. 用户工作规范：保留

| 原规则/来源 | 本轮处置 |
|---|---|
| 分析父目录由用户确定；已有明确路径不应再问（enforcement） | 保留首次确定，不重复确认 |
| `<NN>_ModuleName/`，`scripts/{stages,config,utils}`，`results/{data,tables,plots}`（worker/planning） | 保留；Task 可选不意味着产物目录可随意 |
| 不在 Task 下写分析产物，不建模块 README、logs/、99_Report/ | 保留 |
| 旧模块保留、增量分析复用输出并使用后续模块编号 | 保留；用户明确请求重跑不受影响 |
| figure-standards 的 32 条、PNG+PDF、DPI、配色、字体、图内标注限制 | 原文件不变；不以简化框架为由放宽 |
| 有独立表格且图型受支持时使用 R visualization，否则 Python | 保留；这是既有成图选择约定，不擅自当作模型补丁删除 |
| 临时探索图与最终图分开存放 | 保留 `tmp/` 与 `results/plots/` 边界 |
| 长计算的 tmux wrapper、日志/status/manifest 路径 | 保留；放开主代理使用，不再仅限 worker |
| 正式报告按需、中文自包含 HTML、Report/、四段内容与复现索引 | 保留；无 Task 时以主题代替 TaskID，不补建空计划 |
| Publication 一图一 Notebook、相对路径、单图 PNG+PDF、无大数据复制、实际 Run All | 保留 |
| 用户明确请求才 commit/push，取消问题不能视作同意 | 保留 |

运行时短规范独立在 `core/conventions.ts`，人类可读说明见 [conventions.md](conventions.md)。此层同时供主代理和可选子代理使用，与调度策略分离。

## B. 科学/工程正确性：保留目标，改进验证方式

| 要求 | 本轮处置 |
|---|---|
| 先理解数据、样本/重复结构、对比和混杂因素 | 保留；主代理可直接检查，不依赖 Scout 身份 |
| 科学意图与关键决策充分沟通 | 保留；已有答案可复用，不强制参数依赖树或最终契约按钮 |
| 不能编造数据、结果、引用或用 mock 填补分析失败 | 保留 |
| counts、归一化、全基因/HVG 等数据语义 | 领域 Skills 保留，不删除其中的 data contract |
| 方法假设、统计单位、效应量、多重校正、适用的 CI | 保留；不能用 Skills 文本当外部科学真值 |
| 随机种子、包版本、输入/参数/输出索引 | 保留；实际代码和配置是复现依据 |
| 完成必须有真实执行和内容验证 | 保留；进程零退出/文件存在/勾选不是科学验收 |
| 外部证据需可核验、报告不确定性 | 保留；未核验引用不能假装查过 |

本轮新增的确定性测试验证的是扩展行为、调用数量、参数、取消、错误、超时和规范保持，**不是生物学结果的自动验收**。真实数据正确性与性能收益仍需后续任务测试。

## C. 能力补偿/调度机制：替换或取消

| 旧机制 | 新策略 |
|---|---|
| 每次动作前 NEW/CONTINUE/QUERY 分类 | 根据任务直接工作；不引入另一套状态机 |
| 强制 Scout → 对话 → Task → Worker → Reviewer | 主代理执行；各专家工具按需 |
| 每一步新 Worker + 自动 Reviewer | 一次可选委派只启动一个 worker；独立 review 显式调用 |
| Reviewer 独占计划更新 | 执行者验证后更新自己负责的进度；reviewer 不改文件 |
| 每个分析都必须有完整 Task | 简单任务无文件，多步短清单，长项目按需 Task |
| 结构化问答字段、分支依赖、单轮配额、最终契约门禁 | 仅 question 必填；解释/推荐/选项按需；顺序执行 UI |
| 自动回放并每轮注入完整契约 | 正常会话历史保存答案；`/science-contract` 按需查看当前分支记录，兼容旧结果 |
| Worker 必须 JSON-only，Reviewer 只看自报清单 | 简短交接即可；reviewer 核对预期产物，不盲信自报清单 |
| before_agent_start 强制重新启用所有 Scientist 工具 | 尊重 Pi 工具选择；禁用不会被扩展反向开启 |
| 子代理可意外再次加载 Scientist 调度 | 子进程保留 Skills，跳过本扩展的工具/对话注册，并排除调度工具 |

## D. 尚未确定归属：保守保留/不扩大范围

- 固定 seed=42、R 绘图条件、禁止模拟数据的宽泛表述：可能同时含个人偏好和能力补偿。本轮保留默认，不扩展成模拟实验功能。
- 特定机器的联网端口、数据库位置、工具安装方式：不属于本轮流程改革，不能据此改动主机配置。
- figure-standards 对特定图型是否需要例外：本轮不自行重解释或放宽，遇到冲突明确告知用户。
- PROJECT-MEMORY-DESIGN.md 是改革前保留的历史设计，仍未实施。其旧角色/流程描述不参与新运行时规则。

## 混合规则拆解示例

“Reviewer 验证后才能勾选” → 保留真实进度和验证证据，取消特定角色独占。

“先 Scout 再签契约才能计划” → 保留数据理解、科学意图和关键授权，取消固定代理/状态机/计划前置。

“只能 Worker 用 tmux” → 保留长计算与日志规范，取消调用者身份限制。

本轮不提供第二套 legacy/light 切换框架；历史版本由 Git 恢复点保留，避免双套提示持续漂移。
