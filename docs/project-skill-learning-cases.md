# 项目技能学习：验收与消融记录

对应[实现说明](project-skill-learning.md)。分开报告确定性功能验证与真实模型实验，不把测试夹具当科研数据。

## 1. 确定性验收

学习相关测试覆盖：

- 克隆当前活动分支，保留 compaction/context edit，不夹带放弃的旁支或之后的新任务，不改变主会话。
- 登记后等待正常 settled，包含最终交付回复；取消、普通 idle 与重复事件不触发。
- 交付键去重，后台超时、关闭取消、失败留档及后续手动重试。
- SDK 实际加载只有 evidence_read，无 shell、写入、插件、MCP 或自动发现技能。
- 项目技能通过 Pi 原生发现，只有 reload 后可见，遵守项目信任与 noSkills。
- no_change 不生成空技能；一个主题内整组 hold，不阻塞其他独立主题。
- 同一交付创建多个分析主题，各有独立描述；已有主题须 skill_read 后局部更新，不新增同义任务副本。
- 12 个主题的目录可超过单次八主题上限与单文件正文预算；这些额度不是项目总量限制。
- 目录保存每个主题的冻结基线；无关主题变化不冲突，目标冲突时返回逐主题失败/partial。
- 目录与 frontmatter name 均为主题原名，无项目哈希前缀；新配置仅含 enabled。
- 按主题回退互不影响，旧版配置、混合技能与发布回退兼容；人工同名文件只读。
- 旧前缀主题只读，短名冲突禁止自动更新；旧记录回退只操作原路径，不改短名文件。
- 引文未读/伪造、证据变化、技能基线变化时拒绝发布。
- 唯一原文匹配、不重叠补丁、内容预算、已存在追加内容去重。
- 路径穿越、私有路径、越界符号链接、二进制、大文件、接管人工技能均被拒绝。
- 发布互斥、学习关闭后禁止发布、旧发布回退不覆盖后来的修改。
- 学习配置损坏不阻塞普通分析，工具筛选不被绕过。

命令：`npm test`。默认不调用付费模型；学习测试位于 `tests/learning*.test.mjs`。

## 2. 功能消融：哪些机制不能删

命令：`npm run test:learning-ablation`。

在临时编译副本中逐个移除机制，运行同一组 31 项核心测试。生产代码不包含实验开关。
这是**机制消融/变异测试**，证明相应保证丢失，不是模型质量的统计实验。

| 条件 | 通过 / 失败 | 丢失的保证 |
|---|---:|---|
| 完整实现 | 31 / 0 | 基准 |
| 活动分支筛选 → 全部 entries | 30 / 1 | 把已放弃旁支带进复盘快照 |
| 移除证据来源与版本核对 | 29 / 2 | 未读/伪造引文、后来已变化的证据可发布 |
| 移除技能基线检查 | 29 / 2 | 过时提案覆盖新内容，逐主题冲突失效 |
| 移除风险分类门槛 | 29 / 2 | hold/科学决策变更生效，部分发布分类失效 |
| 将所有 topic 映射到同一个文件 | 23 / 8 | 主题命名、创建、目录扩展、局部更新、回退及基线失效 |
| 移除已有主题必须先读取的条件 | 30 / 1 | 可在未读正文时修改已有 skill |
| 排他发布锁 → 可覆盖锁 | 30 / 1 | 抢占其他发布者的锁 |
| 移除受管路径符号链接检查 | 30 / 1 | 写入路径不再可靠地限制在受管位置 |

每次运行保存完整 TAP 与 JSON 汇总至 `/tmp/scientist-learning-ablation-*`；路径由脚本输出。
这些检查应保留。测试证明的是具体反例，不宣称在所有并发/恶意文件系统条件下形式化安全。

## 3. 初版真实模型小型消融（v1 历史记录）

以下表格是单文件 v1 的历史运行结果，不作为新版多主题实测结果。`npm run test:learning-live` 已适配新提案协议，可重新运行三条件对照；需要 `PI_PROVIDER` / `PI_MODEL`，明确产生模型费用，不随普通测试运行。

### 实验设置

- 模型：`openai-codex / gpt-6-astra`，thinking level 为 low。
- 一个受控的两行元数据夹具，三个条件各运行一次。
- 两个字段都唯一，但项目语义只有历史中说明：`tag_b` 是稳定样本标识，`tag_a` 是临时导出行码且带前导零。
- `metadata.tsv` 由测试程序生成；`validation.json` 的唯一性、缺失值和前导零检查由程序实际计算，明确标记为测试夹具，不是生物学结果。
- 三组得到相同的交付摘要与原始文件。历史消融只清空复盘 session 的继承 entries；读取消融只关闭 evidence_read。其他提示词与发布检查不变。
- 运行真实的 SDK 复盘与发布代码，但所有读写均在独立临时项目内；未在真实分析项目上启用学习。

### 观察结果

| 条件 | 实际结果 | 总 tokens¹ | 时间 |
|---|---|---:|---:|
| 历史 + 证据读取 + 发布检查 | published：保留字符串类型、使用 tag_b 连接，并写明依据、局限与未来检查 | 3,343 | 18.25 s |
| 去掉继承历史 | no_change：确认了文件表面检查，但没有把未知的项目字段语义猜成规则 | 2,696 | 22.05 s |
| 去掉证据读取 | no_change：明确表示无法回查文件，不把用户约定伪装为执行验证 | 798 | 5.89 s |

¹ 各组新产生的 assistant 消息 usage.totalTokens 之和，包含重复输入；不是最终上下文长度，也不是主会话累计消耗。
no_change 表示没有修改技能；到底是没有新知识还是证据不足，见 proposal.summary，不能仅凭状态推断。

完整方案的实际技能明确指出：这些检查只支持当前夹具，不证明未来导出中的身份稳定性；每次新输入都要重新检查唯一性、缺失和未匹配项。这符合预期边界。
原始 session、提案、usage 与汇总保存在 `/tmp/scientist-learning-live-fB4HkY/`，受控夹具可通过脚本重建。

实验脚本最初未初始化 Pi CLI 的代理感知 HTTP dispatcher，三组均报 fetch failed；这些基础设施失败未计入上表。补齐相同网络初始化后才得到上述三组正常结果。没有修改机器代理设置。

### 能与不能得出的结论

- 在这个案例中，继承历史提供了交付摘要/产物本身缺少的项目语义；证据读取提供了可复查的事实依据。两者都值得保留。
- 不把“没有发布”判成模型失败：对于缺少前提或证据的分支，拒绝猜测恰好是期望行为。
- 样本量只有一个场景、每条件一次，没有置信区间；不能证明普遍收益、最优模型或最优提示词。
- 尚未完成真实长期项目上的后续任务 A/B 测试；科学正确性仍需实际验证和用户纠正。

## 4. 多主题版：真实模型连续交付验证

命令：`npm run test:learning-topics`，显式付费；同样使用 `openai-codex / gpt-6-astra`、low thinking。
在临时项目中真实运行两次复盘，测试元数据与计数矩阵仅为受控夹具，检查值由测试程序实际计算，不是科研结果。

| 阶段 | 实际结果 | 用时 |
|---|---|---:|
| 同一次交付包含元数据对齐与单细胞输入 QC | 创建 `sample-alignment`、`single-cell-qc` 两个独立 skill，各有触发描述 | 33.95 s |
| 后续只交付元数据缺失标记处理 | 调用 `skill_read("sample-alignment")` 后更新原主题，没有创建第三个 skill；QC 文件逐字未变 | 20.21 s |

五项程序化核对均通过：创建两个主题、复用原主题、实际读取旧正文、元数据规则增加了 literal `NA` 的适用约定、无关主题不变。
模型在更新后的内容中明确要求遇到缺失 ID 时阻止不安全连接，而不是擅自删行或改变科学排除规则。
原始会话、提案、实际文件和汇总：`/tmp/scientist-learning-live-6N9g91/`。
这验证了本案例中的主题拆分与增量复用，不证明所有分析类型都能自动分类正确，也不是长期性能基准。
该记录产生于仍带项目名前缀的版本；后续无前缀命名变更通过本地自动化测试验证，没有重复付费模型调用。

## 5. 最终保留的最小结构

仅两个生产模块，直接由 `index.ts` 注册：

1. **会话执行模块**：显式交付入口、活动分支快照、受限 SDK 分支、取消/预算与结果通知。
2. **存储发布模块**：多个按分析类型划分的 skill、一个主题化提案、来源核对、局部修改、排他锁、逐主题基线与回退记录。项目规模不再被最小模块数限制。

删去旧的独立代理提示词文件，提示词只在运行模块维护。没有再搭建 brief 转述管道、第二审核代理、队列框架、向量库、多文件发布系统或自动晋升模块。

“最小”指满足已定义功能与安全边界的当前最小实现，不是声称用一次实验找到了理论最小架构。下一步应在真实项目使用中验证效果，再决定是否值得增加机制。
