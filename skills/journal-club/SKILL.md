# Journal Club 文献分析技能

> ⚠️ **依赖 Scientist 模式**：本技能使用 `sci_librarian`、`sci_implement`、`sci_review`、`sci_parallel` 等工具，需要先通过 `/scientist` 开启 Scientist 模式。

将一篇科学论文系统化地分解为三个板块的结构化分析文档：**背景**、**材料方法**、**结果**。每个板块独立输出为 Markdown 文件，并在生成后经过事实核查（sci_review），确保内容忠于原文。

---

## 工作流程总览

```
加载论文 → 并行背景调研 → 并行三板块写作 → 并行三板块审查 → 修正输出
```

整个过程分为 **5 个阶段**，其中阶段 2/3/4 均使用并行 agent 以最大化效率。

---

## 阶段 1：加载论文

1. 使用 `read` 工具读取用户提供的论文文件路径。
2. 确定文件类型（PDF / TXT / MD）。
3. **提取论文标题** — 用于后续文件命名：
   - 如果是 PDF，从文件元数据或首页提取标题。
   - 如果是 TXT/MD，从第一行或 `# ` 标题行提取。
   - 如果标题含特殊字符（如 `:` `/` `\`），替换为 `-` 或 `_`。
4. **识别论文结构** — 快速扫描论文，确定：
   - 有哪些主要章节（Introduction、Results、Discussion、Methods 等）
   - Results 部分包含多少个 Figure
   - 作者、期刊、发表年份

---

## 阶段 2：并行背景调研

在理解论文整体内容后，同时启动以下调研任务。使用 `sci_parallel` 一次性调度，各 agent 独立工作：

```json
[
  {
    "agent": "librarian",
    "task": "论文背景调研-核心概念：根据以下论文内容，检索文章中涉及的 2-3 个最核心的知识背景（如关键信号通路、疾病模型、技术创新点），找到相关综述文献和方法论文献。论文内容摘要：[这里填入从论文中提取的abstract和introduction摘要，500字以内]"
  },
  {
    "agent": "librarian",
    "task": "论文背景调研-参考文献追溯：根据论文引用列表中的关键参考文献（重点查看 Introduction 和 Discussion 中引用的综述性文献），检索这些参考文献的摘要和核心发现，评估它们如何构成本文的研究基础。论文参考文献列表：[这里填入论文引用的5-10篇最相关参考文献]"
  }
]
```

**注意**：此阶段完成后，收集两个 librarian 的结果，汇总后传递给下一阶段各写作 agent 的 `context` 参数中。

---

## 阶段 3：并行三板块写作

使用 `sci_parallel` 一次性调度 **3 个 sci_implement agent**，同时写作三个板块。

每个 agent 的 `task` 和 `plan` 参数中必须包含：
- 完整的论文原文内容
- 阶段 2 的背景调研结果
- 该板块的详细格式要求（见下方）

### 板块 A：背景

**agent**: `worker`（通过 sci_parallel 的 implement 类型）
**task**: 撰写论文背景分析板块
**plan**: 背景板块写作计划

#### 格式要求

```
# 背景 —— 《论文标题》

## 研究背景概述
[一段话概述本文的研究领域、核心问题和本文的贡献，200-300字]

## 知识背景模块

### 知识背景 1：[背景名称]
[整理成段落文稿，解释该知识背景的核心概念，以及它为何是理解本文所必需的]
- **与本文的关联**：[解释该背景如何与本文的研究问题链接]
- **关键参考文献**：
  1. [作者, 年份, 期刊, 标题, DOI/PMID]
  2. ...

### 知识背景 2：[背景名称]
[同上结构]

### 知识背景 3：[背景名称]（如有）
[同上结构]
```

**写作步骤**：
1. 从论文的 Introduction 中提取最核心的 2-3 个知识背景
2. 结合阶段 2 调研的综述文献，为每个知识背景撰写说明段落
3. 确保每个背景都列出至少 2 篇关键参考文献
4. 所有陈述必须有文献依据 — 不得凭空编造

---

### 板块 B：材料方法

**agent**: `worker`（通过 sci_parallel 的 implement 类型）
**task**: 撰写论文材料方法分析板块
**plan**: 材料方法板块写作计划

#### 格式要求

```
# 材料方法 —— 《论文标题》

## 一、样品来源

### 1. [样品类型 1]
- **来源**：[说明样品来源，如临床队列、动物模型、公共数据库]
- **特殊说明**：[如有特殊采样方式、伦理审批、纳入排除标准等，在此说明]

### 2. [样品类型 2]（如有）
- **来源**：...
- **特殊说明**：...

---

## 二、主要技术

### 1. 组织处理技术
#### (1) [技术名称]
- **用途**：...
- **流程简述**：...
- **是否为本文特色**：是/否。若是，则额外说明其创新之处。

#### (2) [技术名称]（如有）

### 2. 分析技术与方法
#### (1) [技术名称，如 scRNA-seq]
- **平台/试剂**：...
- **分析流程**：...
- **关键参数**：...

#### (2) [技术名称，如 光谱流式细胞术]

### 3. 机制验证实验
#### (1) [技术名称，如 TGF-β体外诱导实验]
- **目的**：...
- **方法简述**：...
- **是否为本文特色**：...

---

## 三、本文特色技术深度解析

[对论文中最具特色或创新性的 1-3 项技术进行更详细的说明，包括：
- 技术原理
- 本文中的具体应用方式
- 相较于传统方法的优势
- 可能的局限性]
```

**写作步骤**：
1. 从论文的 Methods 部分（及 Figure Legends）提取所有技术方法
2. 按「样品来源 → 组织处理 → 分析技术 → 机制验证」的逻辑分类
3. 对**特殊的小鼠模型**（如人源化小鼠、转基因模型）和**人体样品采样方式**给予特别说明
4. 识别本文的**特色/创新技术**，单独深度解析
5. 使用分点列表，确保格式清晰

---

### 板块 C：结果

**agent**: `worker`（通过 sci_parallel 的 implement 类型）
**task**: 撰写论文结果分析板块
**plan**: 结果板块写作计划

#### 格式要求

```
# 结果 —— 《论文标题》

## 结果概览
[一段话概述本文的总体研究发现和研究脉络，150-200字]

---

## 结果一：[该结果的标题]

### 科学问题
[该结果要回答的科学问题是什么]

### 整体思路
[作者如何设计实验来回答这个问题]

### 结论
[该结果的核心结论，一句话]

### 结果图表

#### Fig. Xa [图表标题]
- **一句话摘要**：[该图展示了什么]
- **实验方法**：[用什么技术/样本/条件得到这个图]
- **实验结论**：[从该图可以得出什么结论]

#### Fig. Xb [图表标题]
[同上结构]

---

## 结果二：[该结果的标题]
[同上结构]

---

## 科学逻辑链
[用 2-3 段话串联所有结果，说明：
- 承上：上一个结果如何引出本结果的问题
- 本结果回答了什么
- 启下：本结果又引出了什么新问题]
```

**写作步骤**：
1. 从论文的 Results 部分和 Figure Legends 中提取所有结果
2. 按论文的逻辑顺序组织（通常对应 Figure 1 → Figure N）
3. 对每个结果板块：
   - **科学问题**：从上一结果的「启下」或本段开头提取
   - **整体思路**：从实验设计推断
   - **结论**：从结果段的末尾或 Discussion 开头提取
4. 对每个子 Figure：
   - **一句话摘要**：从 Figure Legend 的开头句提取
   - **实验方法**：从 Methods + Figure Legend 提取
   - **实验结论**：从正文中该图对应的描述提取
5. 最后撰写**科学逻辑链**：展示 Figure 之间的逻辑推进关系

---

## 阶段 4：并行事实核查

三个板块写作完成后，使用 `sci_parallel` 一次性调度 **3 个 sci_review agent**，核查每个板块是否忠于原文。

```json
[
  {
    "agent": "reviewer",
    "task": "核查背景板块是否忠于论文原文，所有陈述是否有文献依据，知识背景是否准确反映了论文的研究基础",
    "files": ["背景_<论文标题>.md", "<原始论文文件路径>"],
    "focus": "事实核查：背景板块文献分析。检查：(1) 知识背景描述是否准确反映论文内容，(2) 引用的参考文献是否真实存在于论文中，(3) 背景与论文研究问题的关联是否被正确表述，(4) 有无凭空编造的事实。"
  },
  {
    "agent": "reviewer",
    "task": "核查材料方法板块是否忠于论文原文，技术描述是否准确，分类是否合理",
    "files": ["方法_<论文标题>.md", "<原始论文文件路径>"],
    "focus": "事实核查：材料方法板块。检查：(1) 样品来源描述是否与论文Methods一致，(2) 技术描述是否准确，(3) 特色技术解析是否正确，(4) 有无遗漏重要方法或编造不存在的技术。"
  },
  {
    "agent": "reviewer",
    "task": "核查结果板块是否忠于论文原文，图表描述是否准确，科学逻辑链是否合理",
    "files": ["结果_<论文标题>.md", "<原始论文文件路径>"],
    "focus": "事实核查：结果板块。检查：(1) 每个Figure的描述是否与原文一致，(2) 实验方法和结论是否准确，(3) 科学逻辑链是否正确反映了论文的逻辑推进，(4) 有无编造不存在的数据或图表。"
  }
]
```

---

## 阶段 5：修正与输出

1. **读取所有 review 结果**。每个 reviewer 会报告发现的 issue（按严重程度：Critical / Warning）。
2. **修正所有 Critical 和 Warning 问题**：
   - 对于事实错误：直接修改文档，使其与原文一致
   - 对于遗漏：补充相关内容
   - 对于过度推断：删减或修改措辞
3. **重新核查**（如需要）：如果修正量较大，对修改后的板块再次运行 sci_review。
4. **保存最终文件**：
   - `背景_<论文标题>.md`
   - `方法_<论文标题>.md`
   - `结果_<论文标题>.md`
   - 所有文件保存到与论文原文**同一目录**下

---

## 输出规范

### 文件命名
- `背景_<论文标题>.md`
- `方法_<论文标题>.md`
- `结果_<论文标题>.md`
- 论文标题中如有 `:` `/` `\` `?` `*` 等非法文件名字符，替换为 `-` 或 `_`
- 标题过长时（>50字符），截取前 50 字符

### 语言
- 全部使用**中文**输出
- 专业术语保留英文原名并附中文翻译，如 "NK 细胞（Natural Killer cells）"
- 首次出现的缩写需给出全称

### Markdown 格式
- 使用规范的 Markdown 标题层级（`#` → `##` → `###`）
- 列表使用 `-` 开头
- 图表引用使用 `**Fig. Xa**` 加粗格式
- 参考文献使用编号列表

---

## 并行调度策略

本技能最大程度利用并行 agent 来缩短总耗时：

| 阶段 | 并行数 | agent 类型 | 说明 |
|------|--------|-----------|------|
| 阶段 2 | 2 | sci_librarian × 2 | 背景调研完全独立 |
| 阶段 3 | 3 | sci_implement × 3 | 三个板块内容独立，可同时写作 |
| 阶段 4 | 3 | sci_review × 3 | 三个板块审查独立，可同时核查 |

**关键原则**：
- 每个 agent 获得**完整的上下文**（论文内容 + 阶段 2 调研结果），不依赖其他 agent 的输出
- sci_parallel 中的每个 task 是完全独立的任务描述 — agent 之间不共享上下文
- 阶段间是**串行**的（2 → 3 → 4），因为后一阶段依赖前一阶段的产物

---

## 错误处理

- **论文文件无法读取**：提示用户检查文件路径，尝试其他读取方式（如对 PDF 先用外部工具转文本）
- **论文标题无法提取**：使用文件名（去除扩展名）作为标题
- **论文中某板块内容缺失**（如无独立 Methods 章节）：从全文提取相关描述，在输出中标注「原文未设独立章节，内容从全文提取」
- **review 发现大量错误**：暂停并告知用户，请用户确认是否继续或提供更清晰的论文版本
- **论文包含大量图表而文字描述简略**：尽力从 Figure Legends 提取信息，标注「原文描述简略」
